# 下一阶段设计：显式云端 Camera Agent 与参数直应用

> 状态：沉浸式原生 UI、用户显式单帧多模态请求已实现；当前请求成功后仍弹确认窗。下一步规划为安全校验后直接应用云端建议；不做自动/低频采集。
> 适用基线：Camera Agent MVP 阶段 A–D；多品牌真机验证仍按设备矩阵独立推进

## 1. 目标与边界

在现有端侧相机闭环上，用户主动点击后采集一张当前画面并发送给云端 Agent。Agent 返回可解释的构图、色彩和相机参数建议后，客户端进行本地 schema、时效、能力和数值范围校验，再直接应用支持的参数，不弹二次确认窗。界面应及时反馈已应用、部分应用或未应用的结果，并提供一键撤销/恢复请求前状态。

云端是建议引擎，不直接控制相机、不接收 CameraX 对象，也不能绕过应用的能力检测、参数范围和用户选择。预览、拍照、基本场景提示及已批准建议的执行必须在断网时继续工作。

当前落地内容：UI 已完成沉浸式改造。Agent 页面可编辑 OpenAI 兼容服务配置，默认 `https://api.deepseek.com` 与 `deepseek-flash`。用户点击请求按钮后，客户端通过 ImageCapture 在内存中采集一张 JPEG，最长边不超过 1024 像素、重新压缩后不超过 512 KB，并与结构化摘要一起发送；不写入本地文件。没有应用内固定冷却时间，但同一时刻只允许一个请求。响应解析白名单为 `exposure_ev`、`zoom_ratio`、`color_style`、`composition`，最多 8 项；当前应用前会显示确认弹窗。影调枚举目前为自然、暖调、柔和、鲜明、冷调。相机能力报告已读取变焦、曝光补偿、手动曝光/ISO、白平衡模式、对焦模式及 JPEG 尺寸，但后几项多数仅报告、未实现动态控制。不会上传连续预览流或视频。

本阶段不做：后台或自动上传原始预览帧/照片、持续视频流、云端账号体系、相册同步、无人值守自动拍摄、让模型生成并执行任意代码，或宣称能调用手机厂商私有 ISP 能力。

## 2. MVP 用户流程

1. 用户配置 OpenAI-compatible 服务和 API Key；默认地址为 DeepSeek API。
2. 相机持续使用现有端侧分析。只有用户点击“发送当前画面并获取建议”时才拍摄并发请求；用户可在前一请求结束后再次手动请求，不自动后台触发。
3. 客户端从相机捕获当前单帧并压缩为不超过 512 KB 的 JPEG data URL，与场景、相机参数和能力范围的 JSON 摘要一起发送到配置的 HTTPS 服务；不附带 EXIF、GPS、设备序列号或账号标识，并通过 Authorization header 提供用户配置的 API Key。
4. 服务商返回 Chat Completions 响应。客户端解析限定 JSON 建议；不执行模型返回的代码、工具调用或未知动作。
5. 客户端展示建议与理由，并在严格校验后直接应用所有受支持的动作；不弹确认窗。每项动作显示应用/跳过/失败状态。
6. 应用前再次读取当前 CameraX 状态，验证建议仍然适用于当前镜头和场景，并将每个数值夹在设备能力范围内。仅本地白名单预设可改变成片影调；提供撤销以恢复请求前状态。
7. 网络失败、超时、响应无效或能力不支持时，保留当前相机状态，提供端侧建议或清楚的失败提示，不阻塞取景和拍摄。

## 3. 建议的模块边界

```text
CameraX / ML Kit（端侧实时）
        │ 稳定场景摘要；按需触发
        ▼
  OpenAiCompatibleClient（手动调用）
        │ HTTPS + Chat Completions JSON
        ▼
用户配置的服务商（当前默认 DeepSeek）

生产/多人分发时建议迁移为：Android → 自有 API 后端 → 云端模型

CameraAdvice → 本地 schema/时效/能力/幅度校验 → 参数执行器 → CameraX / PhotoColorProcessor
                                      └→ 应用结果 UI / 撤销
```

- **OpenAiCompatibleClient（Android）**：只响应用户点击，使用 HTTPS、连接/读取超时、响应大小限制和单请求执行器；应用不设固定请求间隔。同一时刻不并发发送请求。不要在 `ImageAnalysis` 每帧回调中直接做网络请求。
- **AdviceRequestBuilder（Android）**：把端侧 `SceneAssessment`、用户选择和能力报告转换为版本化、可审计的结构化输入；默认不持有原始帧。
- **CameraCapabilityValidator（Android）**：对所有返回动作做本地白名单校验、范围夹取和“支持/不支持”判定。云端不得覆盖校验结果。
- **自有后端（后续多人分发方案）**：保存共享模型凭证；验证客户端认证/配额；执行服务端限流；调用所选云端模型并规范化输出。共享密钥不能放进 APK、`BuildConfig`、资源文件或仓库配置。
- **建议展示 UI**：列出改动前后数值、理由和应用状态；不允许模型文本伪装成“已应用”。

当前个人原型已声明 `INTERNET`，仅手动请求时连接用户配置的 HTTPS 地址；`ACCESS_NETWORK_STATE` 仍被移除。API Key 由用户输入并通过 Android Keystore 加密后保存在本机，但请求时会以 Bearer 凭证发送到该地址。Keystore 只保护静态存储，无法防止已解锁设备、被修改的 APK 或调试环境读取运行时密钥。不要把个人 API Key 嵌入 APK 或仓库；多人分发或上线前应迁移到自有后端代理。

## 4. 请求与响应契约草案

### 请求：`POST /v1/camera/advice`

当前 Android 端发送 OpenAI-compatible `POST {base_url}/{chat_completions_path}`，请求体使用标准 Chat Completions 的 `model`、`temperature`、`stream=false` 和 `messages`。消息只含场景/相机能力摘要。若未来增加自有后端，再采用 `POST /v1/camera/advice` 的版本化契约；下面的结构化 JSON 是后端请求体草案：

```json
{
  "schema_version": 1,
  "scene": {
    "category": "portrait",
    "confidence": 0.82,
    "brightness_bucket": "dim",
    "faces_count": 1,
    "subject_position": { "x": 0.48, "y": 0.44 },
    "composition_hint": "subject_centered"
  },
  "camera": {
    "zoom_ratio": 1.0,
    "zoom_range": { "min": 1.0, "max": 4.0 },
    "exposure_ev": 0.0,
    "exposure_range_ev": { "min": -2.0, "max": 2.0 },
    "supported_controls": ["zoom", "exposure"]
  },
  "preference": {
    "style": "natural",
    "goal": "balanced"
  }
}
```

上述数值仅作契约示例。实际请求只能包含设备运行时报告的能力和当前值；不支持的控制不得声明为可用。位置用归一化坐标且只表示当前预览中的主体位置。

### 响应：严格 JSON，不接受可执行文本

```json
{
  "schema_version": 1,
  "request_id": "server-generated-id",
  "expires_in_seconds": 30,
  "summary": "让人像略偏左，并轻微提亮",
  "rationale": "主体居中且当前画面偏暗",
  "suggestions": [
    { "kind": "exposure_ev", "value": 0.5 },
    { "kind": "color_style", "value": "WARM" },
    { "kind": "composition", "value": "subject_left_third" }
  ]
}
```

- `kind` 和 `value` 只能来自客户端定义的枚举；第一版可控动作限于曝光补偿、变焦比例、影调预设和构图提示。
- `composition` 只改变覆盖层/提示，不自动移动手机或裁切取景。
- 不返回任意 Camera2 key、Kotlin/脚本、URL、工具调用或自由格式“动作”。解释文字按不可信输入显示并限制长度。
- 服务端 schema 校验和客户端二次校验都必须存在。解析失败视为无建议。
- 请求/响应加 `schema_version`，向前兼容未知可选字段，拒绝未知动作种类。

## 5. 显式采集、时效与资源控制

产品边界固定为用户显式触发：每次点击只采集和上传一张当前画面，不做自动采集、低频轮询或持续流。

- 手动请求没有应用层固定间隔，同一时刻只允许一个请求；无后台请求或自动重试。服务商自身的速率限制、配额和计费规则仍然适用。
- 当前连接超时 10 秒、读取超时 25 秒；失败后用户可在请求结束后手动重试，服务商可能返回 HTTP 429 或实施自己的限制。
- 当前手动按钮不受端侧置信度阈值或场景稳定时间限制。
- 结果 30 秒后或镜头、场景类别、主体位置显著变化后标记过期；过期建议不得应用，需用户重新显式采集。
- 不在后台运行，不在每帧、每次 UI 刷新或每次曝光更新时联网。
- 没有低频/自动触发的后续计划；如产品方向改变，需另行重新评估隐私、费用与用户控制方案。

## 6. 参数能力扩展设计

参数建议分三层管理，Agent 只输出语义化字段，绝不接受任意 Camera2 key：

| 控制层 | 候选参数 | 接入方式 | 限制 |
|---|---|---|---|
| CameraX 稳定控制 | 曝光补偿、变焦、闪光模式、对焦/测光点 | CameraControl、FocusMeteringAction、ImageCapture | 本机当前已有曝光补偿/变焦部分；镜头能力和绑定状态决定是否生效 |
| Camera2 可选采集/3A 控制 | 曝光时间、ISO、AF 模式/焦距、AWB 模式/色温、色彩校正、色调映射、降噪、锐化、镜头畸变校正、光学防抖、JPEG 质量 | Camera2Interop / CaptureRequest；必要时评估 Camera2 backend | 需读取 CameraCharacteristics 能力、范围与可用模式；与 CameraX 内部请求可能冲突，逐机验证，不做跨机承诺 |
| 应用成片后处理 | 曝光/对比/高光/阴影、色温/色调、饱和度/HSL、曲线/LUT、颗粒、暗角、锐化 | 本地图像处理管线（优先在拍照 JPEG 后处理） | 不等同相机 ISP 控制；RAW/HDR/高分辨率处理的内存与性能需单独验证 |

建议的扩展优先级：P0 先做好建议自动应用、应用结果反馈与撤销；P1 增加预设强度、色温/色调/对比/高光阴影/饱和度等后处理参数；P2 对报告能力的真机增加手动 ISO/曝光时间、白平衡和焦点控制；P3 再评估降噪、锐化、色调映射、畸变校正、防抖与 JPEG 质量。所有动作应声明类别、范围、依赖和失败降级；设备不支持时保留原值并报告跳过。

这些初始阈值是 MVP 产品参数，需用真实设备和服务成本数据调整，不能作为性能承诺。

## 7. 隐私、安全与密钥

- 当前手动请求发送端侧场景类别/置信度/构图提示、当前变焦与曝光、影调预设、设备支持控件及范围，并附带一张单次捕获、最长边 1024 像素且压缩后不超过 512 KB 的 JPEG 图像。图像重新编码以移除 EXIF；不发送视频、持续帧流、成片、精确位置、通讯录、广告 ID 或稳定硬件标识。Authorization header 含用户配置的 API Key。
- 每次仅在用户点击“发送当前画面并获取建议”后采集并上传一张图；图像只在内存中处理，不保存到相册或应用文件。由于图像可能包含人脸或私人场景，页面在发送按钮旁说明图像、结构化数据和 API Key 会发给上方配置的服务。
- 当前 DeepSeek `deepseek-flash` 的官方 [Vision API](https://api-docs.deepseek.com/guides/vision/) 支持 OpenAI-compatible Chat Completions `image_url` data URL 格式；用户配置的其他兼容服务/模型也必须支持图像输入，否则服务端可能返回错误。
- 当前个人原型的用户 API Key 用 Android Keystore 加密后存本机，并在手动请求时发给配置的 HTTPS 服务。此方式不适合共享安装包；公开分发前应迁移到后端密钥管理和短期客户端认证。
- 全链路 HTTPS；不记录原始请求中的图像或可识别信息，不把用户文本拼入系统策略。服务端日志默认不保存请求 body。
- 使用 Android Network Security Config 保持证书验证开启；生产构建禁止明文 HTTP。不要自制证书固定，除非有明确的证书轮换方案。
- manifest 权限最小化；云功能关闭时，相机主功能仍可离线运行。状态栏明确区分“本地建议”“云端建议”“等待/失败”。

## 8. 参数应用安全规则

1. 每次请求由用户显式启动；收到响应后对 schema 合法、未过期、受支持且在范围内的动作直接应用，不弹确认窗。此“直接应用”只针对本次用户主动请求，不表示后台自动采集。
2. 服务端只提供目标值；设备端重新读取当前镜头和能力。曝光索引由 EV 与设备步长换算后取合法值；变焦范围按 ZoomState 夹取。
3. 不支持的参数标成“此相机不支持”，不得静默记入已应用状态。
4. 设置单次变化幅度上限，建议初值为相对请求前曝光补偿变化最多 ±1 EV、目标变焦相对当前倍率不超过 1.5 倍，且不得超过设备能力范围；超限动作应安全夹取或跳过并说明，不能再用确认弹窗放行。阈值须经真机验证后定稿。
5. 在执行前保存本次相机控制状态；提供“撤销本次调整”和“恢复默认”入口。异步 CameraX 操作以 Future 实际完成结果判定，不以提交调用代替成功状态。
6. 直接应用后保留“撤销/恢复此前状态”入口；切换镜头或退出相机时恢复策略明确且可预测。
7. 云端建议不能更改权限、上传图像、拍照、切镜头或开启自动模式。
8. 每条 UI 状态只能在 CameraX future 成功完成后显示“已应用”；失败应恢复显示实际相机状态。

## 9. 错误处理与离线体验

| 情况 | 行为 |
|---|---|
| 用户未开启云端功能 | 仅使用当前端侧建议，不请求网络 |
| 无网络、DNS/TLS 错误、超时 | 保留相机参数，显示可关闭的短提示；允许稍后手动重试 |
| HTTP 429 / 配额限制 | 显示 HTTP 状态；应用不额外设置固定冷却，用户可稍后手动重试，尚未处理 `Retry-After` |
| 服务 5xx | 退避后仅接受用户主动重试；不循环请求 |
| 错误 JSON、未知动作、值越界 | 丢弃该响应，记录不含敏感内容的诊断码 |
| 响应已过期或场景已改变 | 丢弃结果并提示重新显式请求 |
| 控件当前不可用或 CameraX 拒绝 | 展示未支持/未应用原因；其他合法动作可继续执行 |
| 后端/模型不可用 | 端侧场景分析和拍照完整可用 |

## 10. 交付切分与验收

### N1：交互与契约（首版完成）

- 锁定显式请求、返回即直接应用、撤销/恢复入口、最小字段和安全参数白名单；不实现自动采集或低频触发。
- 评审请求/响应 JSON、隐私说明、速率限制和错误状态。

### N2：后端建议代理

- 实现版本化端点、认证/配额、模型调用适配、schema 校验、超时和无敏感请求体日志。
- 用固定的测试响应验证客户端契约，避免测试依赖真实模型输出。
- 密钥从服务器安全配置注入；提供仅含占位值的本地配置示例。

### N3：Android 手动客户端（已实现，设备验收待做）

- 增加手动发送、等待/错误/过期/建议确认 UI 和 HTTPS Chat Completions 客户端。
- 用端侧白名单解析与相机能力范围约束建议；当前仍需用户确认，离线拍摄不受影响。
- 不设客户端固定请求间隔，同一时刻只允许一个手动请求；不做后台触发。真实服务响应与真机网络行为待验收。

### N4：设备与服务验收（下一步）

- 正常建议、超时、离线、429、5xx、非法 schema、越界参数、设备不支持、结果过期、切镜头/场景变化均有覆盖。
- 多品牌 Android 真机上验证 JPEG 单帧捕获/压缩、多模态服务响应、参数合法性、建议应用和错误降级；手动请求无客户端固定间隔，但只允许一个请求在途。
- 核对最终 APK 权限，确认请求只发送单张压缩 JPEG 和获准的结构化字段、不含 EXIF/GPS/视频；扫描仓库与 APK 确认无云服务密钥。
- 不要求加入分析遥测；第一版不采集使用分析数据。

### MVP 完成标准

- 用户未手动发起云端请求时，应用行为和当前离线 MVP 一致。
- 单次手动请求只发送一张用户主动触发采集的压缩图像和契约允许的结构化摘要；不存在持续图像流或视频上传路径。
- 合法建议经过校验后直接应用，不出现确认弹窗；逐项结果以实际 CameraX/图像处理状态为准，并可撤销。
- 断网和所有服务端错误都不会阻塞预览、拍照、相册保存或端侧分析。
- 无效、越界、过期或设备不支持的动作不会被执行。
- 测试包和生产包都不包含模型供应商 API 密钥。

当前已实现手动多模态请求与建议确认弹窗流程；直接应用、撤销和真机服务验收尚未实现。不规划自动低频触发。自有后端代理仍是多人分发前的后续安全工作。

3. 展示简洁的逐项应用状态；保存执行前的相机状态并实现撤销本次 Agent 调整与恢复默认。
4. 扩展设备能力报告和验证矩阵，再按优先级实现白平衡、手动 ISO/曝光、对焦/测光区域、闪光等参数；不支持时明确跳过。
5. 实现本地风格配方和强度滑杆；首批风格建议从褪色胶片、暖色胶片、青橙电影、赛博霓虹、清透日系、人像暖光、美食鲜润、风景旅行、银盐黑白中选取。
6. 完成构建和真机验收：正常/过期/非法响应/范围外/设备不支持/请求失败/撤销恢复，并在两家不同厂商设备记录 Camera2 能力与效果。

用户验收时再在手机上填入自己的 API Key，检查图像与结构化信息确实在显式点击后发送；不要把 Key、原始私人画面或带凭证截图分享出来。

## 12. 后续产品决策

- 云端模型/Agent 供应商、服务部署位置和调用成本上限。
- 后端的部署与认证方式（个人试用可先用自有轻量代理；不建议 APK 直接持有供应商密钥）。
- 预设首批风格与命名、每个预设强度范围、用户自定义配方的存储方式。
- 直接应用的单次变化幅度阈值及是否允许单独关闭某类控制。
- 用户可编辑的拍摄偏好字段与隐私政策/服务数据保留条款。
- 是否把构图建议限定为 overlay 提示，第一版不执行自动裁切/构图变换。

云端调用继续由用户显式触发；这些决策应在增加新预设、更多 Camera2 参数或面向多人分发前确定。
