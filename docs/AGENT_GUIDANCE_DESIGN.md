# Camera Agent 指导闭环设计

> 状态：本轮实现中。产品负责人保留最终验收权。

## 已确认的产品目标

帮助普通用户少试几次、尽快拍到愿意保留的照片；先完善人像、旅行/街拍和美食。Agent 关注画面美感、构图、主体位置与人数关系，不把人物行为识别作为目标。

## 当前实现状态（2026-10-30）

- 取景状态卡提供按场景变化的单选意图；默认自动判断，不要求输入文字。
- 每次请求带 `schema_version=2`、UUID `request_id`、一个新帧、当前相机状态和本会话上一轮结构化结果；上下文只在内存中保存，离开取景页或场景变化即重置。
- 响应须回显版本和请求 ID，并声明主体类别、人数关系、置信度、主体区域、裁剪把握和重取景提示。客户端拒绝过期/错配响应和手动风格锁定下的风格动作。
- 客户端仅在把握达到 0.65、裁剪保留至少 70% 画面且包含全部模型声明主体区域时应用裁剪；应用前扩展为与原图同宽高比的中心框。否则保留完整取景并说明原因。
- 用户可在分析中取消；快门、离开取景页、场景变化或明显画面变化都会使请求失效。压缩阶段检查取消，网络阶段断开 HTTP 连接。
- Debug APK 编译已通过；产品验收和实际设备/模型联调仍由产品负责人后续执行。

## 用户交互

- 默认根据当前取景自动判断；用户可展开轻量的“拍摄意图”入口，最多选择一个场景相关目标，不要求键盘输入。
- 当前确认的意图：人像“突出人物 / 保留环境”；旅行街拍“突出人物或地标 / 展示周围环境”；美食“突出菜品 / 保留餐桌氛围”。默认意图为自动判断。
- 每次分析、重新分析和取消均由用户点按触发。无聊天 UI、后台自动分析或持续上传。
- 分析状态提供短文字和取消入口；普通快门始终可用。用户先拍摄时，当前待返回建议失效，不能稍后改相机或触发自动拍摄。
- 返回建议以简短理由、构图/重拍提示、已应用/跳过/失败结果呈现；不把模型文字伪装成实际执行结果。

## 当前拍摄上下文

上下文仅保存在当前进程/相机拍摄会话内存中，包含当前拍摄意图、上一轮结构化建议及动作执行结果、当前可读取的相机参数和本地场景状态。新请求始终附带一张新的当前帧；不保存或再次上传上一轮图像，不保存自由对话文本，不跨会话记忆。离开主相机 Tab 或切换识别场景时清空上下文。

## 主体、人数与裁剪策略

- 请求允许视觉模型判断主体类别、人数关系（单人、双人、群体、多人/杂乱、无法判断）、主体区域和对应置信度。不得要求判断人物正在做什么动作。
- 如果人物数量、主体区域或裁剪依据不确定，保持普通取景、不应用数字裁剪；可返回简短的重新取景提示。
- 轻微构图修正可返回裁剪框；需要明显移动/拉远/改变角度时，优先返回用户可执行的重新取景提示，让用户移动手机后主动重新分析。
- 裁剪框默认保持用户当前照片比例，且至少保留 70% 的原始取景面积；无法满足主体完整性、比例或面积要求时丢弃裁剪建议。
- 高级 ISO、曝光时间、白平衡等能力仍延期；只允许现有客户端白名单并做能力/范围校验。

## 风格控制权

当前预设选择视为用户明确的风格意图。用户已手动选择预设时，请求必须告诉模型尊重该风格且不提供覆盖预设的动作。用户没有明确选风格时，Agent 才可从本地预设白名单建议风格；用户可以撤销。

## 请求新鲜度与生命周期

- 每个请求使用本地 `request_id` 与 `schema_version`；只接受与当前活动请求匹配的结果。新一轮请求、拍照、切换场景/明显构图变化、取消或页面退出都会使旧结果失效。
- 响应仍须通过当前客户端 schema、动作白名单、设备能力、数值范围、裁剪坐标、比例和面积校验。
- 每次建议最多 30 秒；分析响应前要对比请求时和当前的场景/主体几何信息。明显变化则不应用，提示用户重新分析。
- 取消会关闭当前 HTTP 连接；JPEG 编码检查取消状态并在工作结束时释放本次相机帧资源，避免与编码线程并发关闭帧；普通相机和快门继续可用。
- 每个可执行相机动作保持原有撤销快照；用户主动快门不依赖云端请求状态。

## 个人数据边界

只有用户点击后才上传当前帧与上述最小结构化上下文。请求期间不保存图片；旧图、对话记录、跨会话记忆、行为识别、后台追踪和拍后云端点评都不在本轮。

## 未纳入本轮

- 不做产品负责人验收或人为定义验收通过分数。
- 不做持续视频/流式帧、聊天式自由对话、用户账户/偏好云同步、跨会话个性化、动作识别、拍后云端点评。
- 不开放高级 Camera2 控制；不允许模型执行代码/工具调用或绕过客户端验证。
