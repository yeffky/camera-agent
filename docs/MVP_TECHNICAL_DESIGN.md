# Camera Agent MVP 技术设计

> 状态：阶段 A–D 已实现；三 Tab 导航、风格预设 MVP 与拍摄后原片/成片选择已实现；阶段 E 真机验收待完成；高级相机控制留待后续阶段
> 日期：2026-10-16

## 1. 目标

构建一款无需 root 的独立 Android 相机应用。应用分析实时取景，给出构图建议，并在设备公开相机能力允许时调整拍摄参数和成片色彩。首版先验证手机拍照闭环；通过机型能力探测适配不同品牌。

## 2. MVP 范围

### 包含

- Android 原生 Kotlin 应用，最低 Android 10（API 29）。
- 后置摄像头取景、拍照和保存到系统相册。
- 三分构图辅助线。
- 基础变焦和曝光补偿控制；每个控制项先读取设备支持范围。
- 端侧场景识别、主体定位和影调推荐。
- 自动调整需明确显示当前状态，并提供暂停和恢复默认的入口。
- 可编辑的 OpenAI-compatible Chat Completions 配置、请求预览与用户手动触发的云端参数建议。

### 不包含

- 接管或修改厂商原生相机。
- 调用厂商未公开的 ISP、镜头或计算摄影功能。
- 视频、账号、云同步和运动相机连接。
- 自动云端触发、连续视频上传及超出用户手动请求的一张当前取景帧之外的图像上传。
- 自动/低频采集；云端请求只由用户显式点击发起。

云端 Agent 的请求契约与隐私边界见 [NEXT_PHASE_CLOUD_AGENT_DESIGN.md](NEXT_PHASE_CLOUD_AGENT_DESIGN.md)。Agent 页仅支持用户显式点击后采集并发送一张多模态取景帧；没有后台自动/低频采集，也不上传连续视频流或已拍照片。有效建议经本地校验后直接应用，不显示确认弹窗；支持单次变化限制、执行结果反馈和撤销。

## 3. 用户流程

1. 用户授权相机权限并进入取景界面。
2. 取景画面显示三分线和当前相机控制状态。
3. Agent 从低分辨率预览帧分析场景与主体，生成构图、参数、色彩建议。
4. 云端建议仅在用户显式请求后获取；返回后对校验通过且设备支持的动作直接应用，提供状态反馈、撤销和恢复默认。
5. 用户拍摄，照片保存到 `Pictures/CameraAgent`；选择的影调会在端侧处理后应用于输出照片。
6. 用户可点击 Agent 请求按钮，上传一张压缩的当前取景帧和结构化相机摘要；收到的合法建议自动应用。

## 4. 技术架构

```text
CameraX Preview / ImageCapture / ImageAnalysis
                  │
                  ▼
       本地场景与主体分析器
                  │
                  ▼
       拍摄策略与能力校验器
          ┌───────┴────────┐
          ▼                ▼
     构图提示层        CameraControl
                           │
                           ▼
                  Capture + 本地成片处理
```

### 模块职责

- **CameraScreen / MainActivity：**权限、取景 UI、拍摄控制和状态呈现。
- **CameraXController：**绑定预览与拍照用例，提供相机控制入口。当前代码仍在 Activity 内，后续按实际扩展拆分。
- **CompositionOverlayView：**绘制三分线、人脸框和影调预览覆盖层。
- **AgentSceneAnalyzer：**从 `ImageAnalysis` 获取预览帧，使用 ML Kit 端侧图像标签、人脸检测和亮度采样产生场景、构图及曝光建议。
- **MainActivity 拍摄策略：**依据 CameraX 报告的设备范围应用曝光补偿、人脸测光对焦，并提供辅助/自动模式切换。
- **PhotoColorProcessor：**拍摄后按本地风格预设与强度处理 JPEG，并尽量保留主要拍摄 EXIF 信息；用户可在预览中保存成片或原片。

### 处理策略

- 先只在后置相机的照片模式运行 Agent。
- 分析帧与拍摄帧分离，分析使用较低分辨率，拍摄保留 CameraX 输出质量。
- 每次写入相机参数前读取设备能力和取值范围；不支持的参数显示为建议，不伪报已应用。
- 当前自动曝光使用亮度阈值和设备曝光范围，自动对焦区域在面部位置变化超过阈值时更新；阈值仍需真机调优。
- 图像标签置信度只用于对应类别；未分类场景明确显示“未分类”，避免把最高标签分数误报为场景置信度。
- 场景识别默认端侧完成；仅在用户手动发送云端建议时上传一张重新压缩且移除 EXIF 的当前取景帧，不上传连续预览流或已拍照片。

## 5. 当前实现状态

- 已建立 Android Gradle Kotlin DSL 工程骨架。
- 已实现相机权限请求、后置摄像头预览、拍照保存到 MediaStore。
- 已实现三分构图线、变焦滑杆和曝光补偿按钮。
- 已增加设备能力报告弹窗与复制功能；曝光补偿按钮按支持状态及当前索引边界启停。
- 已接入 ImageAnalysis、端侧图像标签/人脸检测、构图提示、人脸框和自动曝光/对焦建议。
- 已实现辅助与自动模式、影调选择、拍后本地色彩处理；无法使用分析流时退回普通预览和拍照。
- 已实现底部“主界面 / 风格预设 / 模型设置”Tab。风格页含 8 个内置预设、强度、曝光/对比/高光/阴影/色温/色调/饱和度调整、收藏/最近使用和自定义配方管理；拍照后可按住对比成片与原片，并选择保存任一版本。
- 已将场景状态移至取景画面顶部；底部默认仅显示“调控”和“拍摄”，变焦、曝光与高级选项在展开调控面板后显示，以减少对画面的遮挡。
- 已增加手动云端多模态请求：发送一张最长边不超过 1024 像素、压缩后不超过 512 KB 的当前取景帧和场景/相机结构化摘要；没有固定冷却时间，但同一时刻只允许一个请求。响应格式经校验且建议会过期；受支持的曝光、变焦和影调建议直接应用，曝光变化限制在当前值 ±1 EV，变焦单次相对变化不超过 1.5 倍；请求面板显示逐项执行结果并可撤销。
- 当前可执行云端动作包括曝光补偿、变焦、基础影调、本地预设 ID/强度和构图提示；所有预设均从本地白名单读取。能力报告中读取的手动 ISO/曝光、AWB/AF 等能力尚未作为动态控制开放，计划留到后续阶段。预设处理限制见 [PHOTO_PRESET_RESEARCH.md](PHOTO_PRESET_RESEARCH.md)。
- 变焦滑杆监听 CameraX 缩放状态并使用线性缩放接口；无可用缩放范围时会禁用并明确标注。
- Android 37 模拟器上已验证安装、预览、拍照存储、影调成片、权限拒绝提示和能力报告；报告显示该模拟器镜头不支持变焦。模拟器不能替代品牌真机兼容验证。

## 6. 分阶段交付

### 阶段 A：相机基础闭环（实现完成；模拟器已执行验证，真机验收待做）

- 工程可构建并安装。
- 权限允许时可预览、调整基础变焦/曝光、拍照并在相册查看。
- 权限拒绝、相机启动失败和拍摄失败有可见反馈。

### 阶段 B：机型能力探测（实现完成；模拟器报告已采集，真机数据待采集）

- 应用内显示并可复制当前后置相机 ID、硬件等级、闪光、变焦范围、曝光补偿范围、手动曝光/白平衡、AF/AE/AWB 模式和 JPEG 尺寸。
- 根据 CameraX 实时缩放范围和曝光补偿能力禁用不可用控件。
- 用设备能力验证矩阵采集首批真机数据（需要设备实测）。

### 阶段 C：场景与构图建议（实现完成；分类效果待真机验收）

- 加入端侧场景分类和人脸主体检测；本次虚拟场景样例被归类为“通用场景/未分类”，未验证多类别准确率。
- 先输出可解释建议与构图覆盖层，不自动变焦。
- 支持人像、风景、美食、低照度四类初始场景。

### 阶段 D：自动参数与色彩（实现完成；模拟器基础控制已执行验证，成片观感待真机验收）

- 已在模拟器验证曝光从 0 EV 调整到 +0.5 EV，且自动模式可切换；人脸对焦/测光需真实人像场景验证。
- 实现少量影调预设的预览与拍后处理。
- 提供辅助/自动模式切换、暂停和恢复默认。

### 阶段 E：多机型验证（模拟器一款；真实多厂商验证待设备）

- 已采集 Android 37 Google 模拟器报告；未连接任何真实手机，至少两家不同厂商真机验证尚未完成。
- 对照每款设备的能力表检查预览、拍摄、变焦、曝光、色彩一致性和降级行为。
- 根据验证结果决定是否进入视频或运动相机接入阶段。

### 阶段 F：预设与导航迭代（实现完成；真机观感验收待做）

- 底部 Tab 切换相机、风格预设和模型设置。
- 8 个内置本地配方支持强度和色调参数编辑；另支持自定义配方保存、重命名、删除、收藏和最近使用。Agent 只返回内置预设 ID 与强度。
- 拍摄后可预览和比较原片/成片，并分别保存。
- 手动 ISO、曝光时间、白平衡、手动焦距及其他 Camera2 高级控制不在本阶段范围内。

### 阶段 G：拍前预设预览（实现完成；真机流畅度验收待做）

- 取景页增加横向预设选择栏；切换时使用当前本地预设和强度更新预览，不重绑 CameraX 用例。
- 取景影调使用独立 overlay 的轻量色调提示，不在活动 `PreviewView` 上设置 `RenderEffect`，以避免设备上的 CameraX 预览渲染中断；保存照片仍使用完整本地配方处理。
- 预览不模拟逐像素高光/阴影曲线和厂商 ISP；成片仍由 `PhotoColorProcessor` 完整处理，需在真机检查预览与成片差异和流畅度。
- 详细需求见 [OpenSpec：preset-live-preview](../openspec/changes/preset-live-preview/proposal.md)。

### 阶段 H：云端 AI 取景裁剪与拍摄（客户端实现完成；云端联调/真机验收待做）

- 用户点击取景页 AI 拍摄入口后才上传一帧；在当前取景页显示云端建议和裁剪框。
- 响应可包含基于正向、非镜像上传图像的归一化 `crop_rect`；客户端校验坐标、裁剪面积和取景可见范围，再只允许白名单中的曝光、变焦、风格动作。
- 用户默认手动按快门；可在 AI 建议卡片中显式开启 AI 调整成功后拍摄一次。无效/过期/失败或未应用的建议不会触发自动快门。
- AI 裁剪使用原始分辨率 ImageCapture JPEG 的 EXIF 坐标映射，并只保存裁剪输出；裁剪失败时删除未裁剪临时照片并退回普通相机。
- 云端响应、PreviewView 和不同厂商照片方向/比例仍需用真实服务和设备验证；详细契约见 [OpenSpec：ai-framing-capture](../openspec/changes/ai-framing-capture/proposal.md)。

### 阶段 I：拍后轻量预设微调（实现完成；产品验收待做）

- 拍摄结果预览增加 0–100 预设强度滑杆；预览从当前拍摄源重新处理，不重复叠加 JPEG 压缩。
- 拖动期间合并快速更新，处理未完成时禁用保存；重拍或关闭预览不改变预设默认强度。
- 只有照片成功保存后才持久化这次强度；AI 裁剪流程只处理裁剪后的源图，结果页不提供全幅图。
- 规格见 [OpenSpec：post-capture-light-edit](../openspec/changes/post-capture-light-edit/proposal.md)。

## 7. 验收标准

- 无 root，使用公开 Android 相机 API。
- 权限拒绝后不崩溃；授权后可启动预览。
- 拍摄结果保存到系统相册指定目录。
- 曝光和变焦控制始终限制在设备公开报告的范围内。
- Agent 对不可用能力给出明确提示，不宣称已应用。
- 端侧场景分析与照片处理不依赖网络；云端请求失败不影响预览和拍摄。
- 场景类别准确率、辅助建议稳定性和低照度曝光策略尚未在真实场景测定。

## 8. 隐私与权限

- 最终 APK 申请 `CAMERA` 与 `INTERNET`；移除 `ACCESS_NETWORK_STATE`。只有用户在 Agent 页面手动请求时使用网络；相机预览、端侧分析、拍照和存储仍可离线运行。Android 10+ 通过 MediaStore 写入照片，不申请广泛存储权限。
- 用户点击“发送当前画面并获取建议”后，ImageCapture 生成单张 JPEG；客户端缩至最长边 1024 像素以内并重新编码至 512 KB 以内，移除 EXIF 后以 base64 data URL 发往用户配置的 HTTPS 服务。图像只在内存处理，不保存到相册/应用文件；不传连续预览流、视频或已拍照片。图像可能含人脸和私人环境，发送按钮旁已有提示。
- 飞行模式下已验证相机预览、场景分析状态和拍照保存正常；云端服务断网行为仍需按下一阶段清单验收。
- 不接入账号或遥测；云端请求仅由用户手动触发，不做自动轮询。

## 9. 风险与边界

- CameraX/Camera2 的可用参数依机型而异，需运行时探测并做真机矩阵验证。
- 第三方 App 无法保证复现厂商原生相机的专有 ISP 和计算摄影效果。
- 变焦可能是数码裁切，也可能切换物理镜头，设备行为和过渡质量不同。
- 调曝光时画面亮度可能与最终 JPEG 的自动处理存在差异，需在真机确认预览/成片一致性。
- 颜色处理首版基于 App 自己的处理链路，不承诺与原生相机风格完全一致。

## 10. 工程环境与当前验收边界

- JDK 17
- Android SDK Platform 35
- Android Gradle Plugin 8.8.2 / Gradle Wrapper 9.6.0
- Kotlin 2.0.21
- CameraX 1.4.2

工程使用 JDK 17、Android SDK Platform 35、Android Gradle Plugin 8.8.2、Kotlin 2.0.21 和 CameraX 1.4.2。多模态功能的 `:app:assembleDebug` 已成功；已有 Android 37 模拟器验证覆盖此前相机功能，但本轮未在设备上验证图像请求。当前 APK 声明 `CAMERA` 与手动云端请求所需的 `INTERNET`，不声明 `ACCESS_NETWORK_STATE`；飞行模式下相机预览和拍照保存仍正常。云端服务调用尚未用真实 API Key 实测。运行级记录和设备能力报告见 `DEVICE_CAPABILITY_MATRIX.md`；模拟器输出截图与样张位于 `build/`。

阶段 E 的真机验收需要至少两台不同品牌 Android 手机，并逐台检查权限授权/拒绝、预览、前后镜头（若 MVP 当前仅后置则验证后置）、能力报告、变焦/曝光实际变化、自动模式稳定性、拍照保存、影调成片和分析不可用时的降级。采集步骤和记录模板见 `DEVICE_CAPABILITY_MATRIX.md`。
