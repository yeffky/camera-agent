# Camera Agent 产品设计文档

> 状态：方向已由产品负责人确认；分阶段实现中，最终验收由产品负责人执行。
> 更新时间：2026-10-30

## 1. 产品定位

Camera Agent 面向希望快速拍出好照片、但不熟悉构图和相机参数的普通用户。产品围绕拍前与拍中指导展开，拍后只提供轻量风格微调。高级 Camera2 控制不在当前迭代范围。

产品差异点是把 AI 场景理解、取景建议、受限的相机参数应用和拍摄串成一个相机内流程；用户仍然决定是否让 AI 分析、使用哪种拍摄方式，并能看到 AI 改了什么。

## 2. 已确认的产品决策

| 主题 | 已确认方向 |
|---|---|
| 核心用户 | 普通用户，需要构图/场景指导并快速拍出好照片 |
| 主体验 | 拍前/拍中指导为主，拍后轻编辑 |
| AI 触发 | 用户点击 AI 拍摄后，才将当前拍摄画面发送到配置的云端模型 |
| 建议应用 | 云端返回建议后，客户端自动应用当前设备支持的取景裁剪和基础拍摄参数 |
| 裁剪 | AI 可指出应避开的画面区域，例如裁掉左下角杂物并保留右侧内容；最终只保存裁剪版 |
| 快门方式 | 用户可选择确认构图后按快门，或由 AI 调整完成后自动拍摄 |
| 离线降级 | 普通相机和本地预设继续可用，并提示 AI 暂不可用 |
| 风格预设 | 拍前可实时预览；拍后可轻调预设强度 |
| 竞品范围 | 手机原生相机（Pixel、Samsung、iPhone）按拍摄流程比较；Lightroom、VSCO、美图秀秀、醒图按预设、编辑和分享体验比较 |
| 高级控制 | 手动 ISO、曝光时间、白平衡等后续再做 |
| 验收 | 由产品负责人在本轮功能完成后执行；实现期间不要求逐项产品验收 |

## 3. 目标体验流程

1. 用户进入主界面，看到取景画面、当前风格、快门和独立的 AI 拍摄入口。
2. 用户在取景页横向浏览风格预设，预览风格效果；必要时打开预设页调整配方。
3. 用户点击 AI 拍摄，应用捕获一帧并明确显示正在分析。只有此操作会发送画面到用户配置的云端模型。
4. 客户端校验云端返回的建议、时效和设备能力，再应用支持的基础参数和建议裁剪区域。
5. 取景页显示最终裁剪构图和简短理由，并展示已经应用的参数；用户可选择确认后拍摄，或启用自动拍摄。
6. 成片按 AI 指定区域裁剪，只保存裁剪版。拍后可查看照片并微调风格强度。
7. 云端请求失败或断网时，提示 AI 暂不可用，普通相机仍可拍摄。

## 4. 体验设计原则

### 主界面

- 快门保持最显眼；AI 拍摄入口与快门容易区分，避免误触造成云端上传或自动拍照。
- 当前风格以短标签和可见效果呈现；预设选择不遮挡主体和构图提示。
- AI 裁剪边界、主体保留区域和参数变化必须在拍摄前可见。
- 已有“主界面 / 风格预设 / 模型设置”底部 Tab 继续承担一级页面切换；取景页本身承载高频拍摄操作。

### Agent 反馈

- 清楚区分“分析中、已应用、部分应用、未应用、建议过期、请求失败”。
- 对自动修改给出可读理由和简洁的改动摘要；不把模型解释文字冒充设备执行结果。
- 裁剪建议无法转换成设备可用取景区域时，不得静默输出错误构图；回退到普通拍摄并说明情况。
- 自动拍摄是用户明确选择的行为，不在 AI 请求后无提示地触发。

### 动效

- 预设切换以连续、短暂的画面过渡表达效果变化，避免闪白、强烈扫描或遮挡主体。
- AI 返回裁剪时，裁剪框移动或收拢到结果区域，让用户看懂画面怎样变化。
- 参数应用后用简短状态反馈；拍摄完成后反馈保存结果。
- 网络失败时使用明确信息，不依赖无限旋转动画表达等待。

### Android UI 组件与实现路线

- 当前界面使用 Kotlin 原生 Views 和 CameraX `PreviewView`。近期视觉优化优先复用 CameraX 预览，不为样式调整迁移整套相机页。
- 若继续保留 Views，可选用开源的 [Material Components for Android](https://github.com/material-components/material-components-android)，例如 `BottomNavigationView`、`MaterialCardView`、`TextInputLayout` 和 `Slider`。该库目前处于维护模式，不再计划新增 Views 功能，适合作为渐进迁移期间的过渡组件，不宜作为长期 UI 技术路线。
- 后续新增页面或重做设置/预设页时，优先评估 [Jetpack Compose Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3)。其提供 Navigation Bar、Card、Button、Slider 等组件；与现有 CameraX View 可分阶段互操作，待验证相机预览、生命周期、性能及可访问性后再决定扩展范围。
- 本轮先保留原生 Views：优化底部 Tab 的图标、选中态与轻动效，并将模型设置按任务分组。是否引入 Material Components 或逐页迁移 Compose，作为单独技术决策，不和这一轮界面整理绑定。

## 5. 竞品对比结论

| 竞品组 | 代表体验 | Camera Agent 借鉴点 |
|---|---|---|
| 手机原生相机 | [Pixel Camera Coach](https://support.google.com/pixelcamera/answer/17367411?hl=en) 提供场景/构图指导；[iPhone 摄影风格](https://support.apple.com/en-gb/guide/iphone/iph629d2cd37/27/ios/27) 支持拍前风格浏览；[Samsung 相机](https://www.samsung.com/us/support/answer/ANS10001353/) 把常用控制和专业模式分层 | 指导在取景时出现；风格可以拍前选；常用操作直达，低频控制收纳 |
| 编辑与社交影像 | [Lightroom Mobile](https://helpx.adobe.com/lightroom/mobile/work-with-presets/apply-presets.html) 提供预设强度和 AI 辅助编辑；[VSCO Capture](https://support.vsco.co/en/articles/12698469-your-guide-to-presets-in-vsco-capture) 支持拍前预设预览；[美图秀秀相机](https://www.meituxiuxiu.com/zh-Hans/academy/camera) 重视拍前风格；[醒图](https://apps.apple.com/cn/app/%E9%86%92%E5%9B%BE-%E5%85%A8%E8%83%BD%E4%BF%AE%E5%9B%BE%E7%A5%9E%E5%99%A8/id1500526240) 以拍后修图为主 | 预设强度可调，拍后编辑保持轻量；不扩展成完整图库修图器 |

不同机型、地区、系统版本和订阅计划可能影响竞品功能可用性；以上比较的是体验模式，不要求功能逐项对齐。

## 6. 分阶段交付顺序

### 阶段 0：承接已有实现

- 现有三 Tab、本地风格预设库、自定义配方、拍后原片/成片流程和云端建议校验/直应用/撤销作为代码基线。
- 现有未提交变更先单独整理为可追踪版本提交，不与新功能混为一笔。

### 阶段 1：拍前预设实时预览（实现完成）

- 取景页提供当前风格和可横向选择的预设入口。
- 预设切换更新取景效果；最终保存图片应用相同配方和强度。
- 拍后保留强度微调。
- Android 12 及以上使用 GPU 色彩矩阵；Android 10/11 以轻量色调提示降级，取景预览对高光/阴影和设备 ISP 是近似呈现。

### 阶段 2：云端 AI 取景裁剪与拍摄（客户端实现完成）

- 为云端响应增加归一化裁剪框、建议说明及受限参数动作。
- 客户端执行 schema、时效、范围、设备能力校验。
- 在取景页展示裁剪结果，支持用户确认快门或选择自动拍摄。
- 只保存裁剪版；失败时保持普通拍摄可用。
- 客户端已实现显式单帧上传、有限裁剪 schema、取景裁剪框、参数校验/应用/撤销、显式自动拍摄开关和裁剪后输出；仍待云服务返回 crop_rect 的联调和设备验收。

### 阶段 3：统一拍后轻编辑和结果反馈（客户端实现完成）

- 用一致的照片结果页呈现裁剪照片和预设强度微调。
- 清楚反馈保存/分享结果和编辑重置。
- 不加入重型图库、图层、蒙版或高级 Camera2 控制。
- 成片预览已增加强度滑杆；调整时从当前拍摄源重新生成，只有保存成功后才记住新的预设强度。AI 裁剪照片的预览与保存都基于裁剪源。

### 阶段 4：产品负责人验收

- 在阶段 1–3 完成后，由产品负责人执行整体验收和设备实测。
- 设备差异、裁剪画质和服务端模型质量根据验收结果进入下一轮修正。

## 7. 技术与隐私约束

- 云端只接收用户主动触发的一帧；不上传连续预览流或视频。
- API Key 只从本机加密配置读取，不能写入源码、构建配置或 OpenSpec 示例。
- 模型只输出语义字段和有界数值；客户端通过本地白名单校验后才可操作相机。
- 优先复用 CameraX 当前已支持的曝光补偿、变焦和本地预设。手动 ISO、曝光时间、白平衡等高级控制不在当前实现范围。
- 裁剪坐标必须定义基于何种方向、镜像、预览比例和照片坐标空间；最终输出不能只裁预览截图代替原始照片。
- 自动拍摄是显式可选模式；普通快门路径始终可用。
