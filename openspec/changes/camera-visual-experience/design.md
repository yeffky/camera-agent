# 设计：相机页视觉层级与预设反馈

## 视觉架构

保持现有 CameraX PreviewView + composition overlay + 控件叠层。相机内容区域保持独立全屏容器；顶部状态与操作、AI 建议、底部预设与快门分别占据清楚的层级，不让静态文案挡住主体。

使用 `docs/CAMERA_UI_VISUAL_DESIGN.md` 定义的暗色 canvas、卡片 surface、选中态色、AI 强调色、间距与圆角令牌。预设标记使用与 `PhotoPreset`/`ColorStyle` 绑定的色彩点，不用占位照片造成效果误导。

## 交互

- 顶部场景状态由现有 `latestAssessment` 更新；分析尚未完成时显示短暂默认状态。状态信息控制在两行，长构图建议在 AI 详情中阅读。
- 预设横条内每项包含颜色标记与名称；点击继续调用原有 `selectPreset(..., navigateToPresets = false)`，只更新当前本地预设、预览和选中状态。
- AI 建议卡片展示短标题、已有建议文案、原有自动快门开关和撤销按钮。关闭仅隐藏面板，不撤销已应用动作，也不改变快门策略。
- 快门仍为中心主操作；AI 请求仍须显式点击 AI 按钮。建议面板和动效不延迟拍照。

## 动效与无障碍

使用现有 Android View 属性动画，持续时间约 120–200ms，读取系统动画缩放设置。减少动态预览上的大面积模糊、扫描线和重叠动画。按钮为至少 48dp 触控区域，并设置可读的 `contentDescription`/选中状态。

## 生命周期与失败

- 不新增相机流，不调整 PreviewView scaleType、implementationMode 或 CameraX UseCase 绑定。
- UI 层重建时从现有相机/预设/Agent 状态生成展示；没有场景评估时显示稳定占位提示。
- 预设视图刷新失败时保留当前相机预览和快门操作。
- AI 建议更新继续走现有时效、白名单和设备能力校验流程；视觉层只展示结果，不参与动作授权。

## 设备差异

固定间距使用 dp，文本允许换行且对长场景描述限制行数；暗色取景 overlay 保持高对比。后续验收需覆盖窄屏、系统字体放大、横竖屏与不同厂商预览比例。
