# 设计：相机导航与设置页界面整理

## 界面策略

继续使用现有单 Activity + CameraX `PreviewView` 架构。相机预览与控制保持原有 View 层级；底部导航仅通过图标、标签、圆角选中背景和状态色表达选择。选项采用 54dp 高度，满足至少 48dp 的触控区域。

Tab 选中时对应项使用明亮文字、柔和蓝色图标和深蓝灰圆角底色，未选项保持灰色。点按提供幅度很小的缩放反馈，持续约 170ms；页面以约 160ms 淡入，不使用闪白或覆盖预览的转场。

模型设置仍使用竖向滚动表单，将相互相关的模型连接字段、拍摄建议请求、最近建议及请求预览放入独立卡片。现有提示、API Key 处理、请求按钮、撤销行为和内容顺序语义不变。

## 状态与生命周期

- Tab 状态仍由 `activeTab` 持有，页面切换逻辑保留当前实现。
- 模型设置 View 继续缓存，避免页面离开后丢失未保存的表单内容。
- 风格页继续根据当前本地预设状态重新构建，以展示最新选择和收藏信息。
- 快速重复切换时，最终可见页应与最后一次选择相同；动画只用于视觉反馈，不延迟业务状态更新。

## 兼容与失败行为

- 不新增运行时 UI 依赖，不触碰相机绑定、图像分析、拍摄或云端上传路径。
- 页面动画使用普通 View 属性动画；系统动画缩减或低性能设备上仍应可直接完成导航。
- 若页面创建失败，应保留相机页可访问，不改变现有的相机权限和离线行为。

## 后续组件迁移

官方 Material Components Views 库处于维护模式，因此本次不引入它作为全新 UI 基础。后续可先在非相机页面试点 Compose Material 3 与现有 View 互操作，再依据设备验证决定迁移范围。
