# Design: 取景页实时预览风格预设

## Context

预设当前经 `PhotoColorProcessor` 应用于拍摄 JPEG，取景预览与最终成片尚未共用实时效果管线。需要保持低端/旧版 Android 可用，并避免对相机帧做高开销 CPU 逐像素处理。

## Goals

- 用户在按快门前能切换预设并看到连续更新的风格预览。
- 最终保存的照片仍由原始拍摄图像经既有处理器生成，不降低传感器输出分辨率。
- 当前预设、强度和配方状态只有一个事实来源。

## Proposed approach

- 将取景预览风格作为可撤销的显示效果，不改变 CameraX 的 ImageCapture 或 ImageAnalysis 帧。
- 复用 `PhotoPresetStore` 的选中预设、强度和配方；预览状态变更立即刷新效果层。
- 预览实现需根据 minSdk 和 CameraX 版本选择兼容路径；若平台图形效果能力不足，保留普通预览并提供一致的拍后效果，不能声称实时效果已生效。
- 滑杆拖动期间更新预览，但避免为每次拖动重建页面或重绑 CameraX use case。

## Risks

- 预览渲染效果与 JPEG 后处理结果可能存在色域/色调差异；保存输出必须以照片处理器为准，后续设备验收校准观感。
- 视图级效果对截图/系统合成和老设备存在差异，需记录适配边界。
- 取景控件需要留出空间，不能遮挡快门、主体或 Agent 的裁剪覆盖层。

## Rollout

先让取景页切换内置预设和强度，再让同一状态贯穿拍摄后的轻编辑。自定义预设仍沿用本地存储。
